# Phase 4B 기본 매장 상세

## 범위

Phase 4B는 지도 또는 검색 결과에서 선택한 매장의 현재 로딩된 정보를 별도 화면에서 확인하고 주소를 복사하는 기능이다. 상세 화면은 선택된 `StoreLocation` 객체를 그대로 전달받으며 진입 과정에서 Supabase, 데이터 로더 또는 외부 API를 다시 호출하지 않는다.

pilot, staging, supabase 데이터 모드는 모두 같은 상세 화면을 사용한다. production/release 데이터 모드 차단 정책, Supabase SELECT 컬럼, migration과 RLS는 변경하지 않는다.

## 진입과 복귀

- 기존 지도 선택 카드의 `상세보기` 버튼으로 진입
- 마커와 검색 결과 중 어느 경로로 매장을 선택해도 같은 화면 사용
- Flutter 기본 `Navigator` route로 선택된 객체 전달
- 뒤로가기 후 기존 지도 화면, 검색어, 필터된 마커와 선택 카드 유지
- 상세 화면 왕복 중 기존 데이터 로더 추가 호출 없음

## 표시 정보

현재 `StoreLocation`에 존재하는 다음 정보만 표시한다.

- 매장명
- 주소
- 버거 스타일
- 사용자용 검수 상태

버거 스타일이 비어 있거나 `미분류`이면 `아직 분류되지 않았습니다.`로 표시한다. 검수 상태는 다음 사용자용 문구로 변환하며 원본 상태 문자열은 노출하지 않는다.

- `verified`: 검수 완료
- `pending`: 검수 중
- `needs_recheck`: 재확인 필요
- 그 밖의 값 또는 값 없음: 검수 상태 확인 중

내부 UUID, 로컬 candidateId, 외부 Place ID, sourceType, API 정보는 표시하지 않는다. 현재 데이터에 없는 메뉴, 사진, 전화번호, 영업시간, 평점, 리뷰 수를 생성하거나 준비 중 영역으로 채우지 않는다.

## 주소 복사

`주소 복사` 버튼은 Flutter 기본 Clipboard API로 현재 주소 문자열을 복사한다. 성공 시 `주소를 복사했습니다.` SnackBar를 표시한다. 주소가 비어 있는 예외 상황에서는 Clipboard를 호출하지 않고 `복사할 주소가 없습니다.`를 표시한다.

외부 지도 앱 실행, URL 열기와 위치 권한은 포함하지 않는다.

## UI와 접근성

- 명시적인 뒤로가기 아이콘과 tooltip
- 상세보기 및 주소 복사 버튼의 텍스트, 아이콘, tooltip
- SafeArea와 SingleChildScrollView 적용
- 긴 매장명과 주소를 줄임 없이 여러 줄로 표시
- verified 상태는 기존 색상 체계의 절제된 배지로 표시
- 상세 화면에 별도 Google Map을 추가하지 않음

## 자동 검증

위젯 테스트에서 검색 결과로 선택한 `StoreLocation`과 상세 화면에 전달된
객체가 동일한지 확인했다. 상세 화면에 진입했다가 뒤로 돌아온 후에도 검색어와
선택 카드가 유지됐으며, 이 왕복 과정에서 Supabase 데이터 로더 호출 횟수는
최초 1회로 유지됐다. 상세 화면은 전달받은 객체만 사용하므로 추가 Supabase
SELECT 또는 외부 네트워크 요청 경로가 없다.

## Android 수동 검증

2026-08-20 Android 에뮬레이터에서 사용자가 다음을 확인했다.

### Development + staging

- staging 매장 24개 로딩
- `PPS` 검색 후 결과 선택 및 상세 화면 진입
- 상세 화면의 매장명과 주소 표시
- `미분류` 버거 스타일이 `아직 분류되지 않았습니다.`로 표시
- `pending` 상태가 `검수 중`으로 표시
- 주소 복사 후 `주소를 복사했습니다.` 안내 표시
- 뒤로가기 후 `PPS` 검색어와 선택 카드 유지

### Development + supabase

- 공개 매장인 노머시버거 상세 화면 진입
- `verified` 상태가 `검수 완료`로 표시

수동 검증 과정에서 Supabase 데이터, migration, RLS 또는 실제 매장 행을
변경하지 않았다.

## 후속 데이터

메뉴와 리뷰 기능은 실제 DB 스키마, 출처 정책, 사용자 생성 데이터 검수 및 RLS 정책이 준비된 이후 단계에서 별도로 구현한다. 실제 데이터 계약이 정해지기 전에는 화면 placeholder나 가짜 값을 추가하지 않는다.
