# 데이터 출처 정책

## 후보 생성 원천

Burger Map Korea는 소상공인시장진흥공단의 상가(상권)정보 공공데이터를 매장 후보 생성 원천으로 사용한다. 원본 파일마다 다음 정보를 별도로 확인해 기록한다.

- 제공 기관과 데이터셋 이름
- 다운로드 경로
- 원본 기준일(`sourceAsOf`)
- 다운로드 또는 확보 일자
- 적용된 추출기 버전 또는 Git commit

Phase 2.1A 스크립트는 기준일을 자동 추측하지 않는다. 실행자가 원본 자료에서 확인한 실제 기준일을 `--source-as-of`로 입력해야 한다.

## 원본과 파생 데이터

- `data/raw/`: 공공데이터 원본. 로컬 처리 전용이며 Git에 포함하지 않는다.
- `data/review/`: 자동 생성된 검수 후보. `pending` 또는 `needs_recheck` 상태이며 앱에 노출하지 않는다.
- `data/verified/`: 향후 사람의 검수를 통과한 데이터만 두는 위치다. 이번 Phase에서는 생성·승인 파이프라인을 구현하지 않는다.

공공데이터의 상호명, 주소, 업종, 좌표는 출력 시 임의로 고치거나 보완하지 않는다. 비교용 문자열 정규화는 필터와 중복 의심 판정에만 사용한다.

## 외부 장소 API

Google Places API, Kakao Local API, NAVER Local/Search API는 영구 매장 DB의 원천으로 사용하지 않는다.

Phase 2.1B에서는 카카오맵 키워드 장소검색을 공공데이터의 누락 후보를 찾고 기존 후보와 대조하는 제한된 수동 검수 도구로만 사용한다. 원본 JSON은 저장하지 않고 필요한 장소 필드만 별도의 `data/review` CSV에 기록한다. 전화번호, 리뷰, 사용자 정보는 수집하지 않으며 카카오 결과를 공공데이터 CSV, Flutter 데이터 또는 영구 매장 DB에 자동 병합하지 않는다.

카카오 보완 후보의 장기 보관, 재배포 또는 앱 노출은 이용약관과 검수 근거를 별도로 확인한 뒤 결정한다. API 결과만으로 실제 매장 여부를 승인하지 않는다.

## 앱 노출 원칙

자동 추출 결과는 실제 매장으로 간주하지 않는다. 사람이 영업 상태, 버거 전문성, 주소와 좌표를 확인해 `verified`로 승인한 매장만 향후 앱에 노출한다. Phase 2.1A에서는 Flutter 앱 반영을 하지 않는다.
