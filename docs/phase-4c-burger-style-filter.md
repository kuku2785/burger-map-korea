# Phase 4C 버거 스타일 필터와 승인 데이터

## 범위

Phase 4C-A는 이미 로딩된 매장을 단일 대표 버거 스타일로 필터링하는 구조를 추가했다. Phase 4C-B2는 사용자가 승인한 스타일만 원본 staging CSV와 분리된 development용 asset에 반영한다. Supabase SELECT, migration과 RLS는 변경하지 않는다.

## 분류 체계

내부 저장 코드와 사용자 표시 문구를 분리한다.

| 내부 코드 | 사용자 표시 |
| --- | --- |
| `classic` | 클래식 |
| `smash` | 스매시 |
| `chicken` | 치킨 |
| `plant_based` | 비건·식물성 |
| `other` | 기타 |
| `unclassified` | 미분류 |

`StoreLocation.burgerStyle`은 staging JSON과 Supabase 로더의 기존 문자열 계약을 보존한다. 앱 도메인의 `BurgerStyle` enum이 문자열을 타입 안전하게 파싱하고 UI에는 `displayLabel`만 전달한다.

영문 내부 코드는 앞뒤 공백과 대소문자 차이를 정규화한다. 표의 한국어 문구와 기존의 명시적인 한국어 별칭도 파싱한다. 빈 값, null에 해당하는 입력과 알 수 없는 문자열은 예외를 발생시키거나 임의 분류하지 않고 `unclassified`로 처리한다. 상세 화면에서는 `unclassified`를 기존 문구인 `아직 분류되지 않았습니다.`로 표시한다.

## 필터 UI

- 첫 항목은 항상 `전체`
- 현재 로딩된 매장에 실제로 존재하는 스타일만 표시
- enum 분류 순서로 정렬하고 중복 제거
- 가로 스크롤 가능한 ChoiceChip 사용
- 선택 상태와 접근성 label 제공
- B2 development asset은 `전체`, `클래식`, `스매시`, `치킨`, `기타`, `미분류`를 분류표 순서로 표시
- `plant_based` 매장이 없으므로 `비건·식물성`은 표시하지 않음

필터 항목 생성은 메모리의 로딩된 매장 목록만 사용하며 Supabase 요청을 추가하지 않는다.

## 검색 결합

검색어와 스타일은 AND 조건으로 적용한다. 같은 결과 목록이 지도 마커, 검색 결과 목록, 결과 없음 안내와 선택 카드 유효성에 사용된다.

- 검색어 지우기: 선택 스타일 유지
- `전체` 선택: 현재 검색어 유지
- 필터에서 선택 매장이 제외됨: 선택 카드 닫기
- 필터 변경: 지도 카메라를 이동하지 않음
- 상세 화면 왕복: 검색어, 선택 필터, 선택 카드와 지도 상태 유지
- 데이터 재로딩 후 선택 스타일이 새 목록에 없으면 `전체`로 안전 복귀

검색과 필터 변경은 기존 로더가 반환한 `List<StoreLocation>`만 사용한다. 입력, 필터 전환과 상세 화면 왕복으로 데이터 로더 또는 Supabase SELECT를 다시 실행하지 않는다.

## 실제 데이터 정책

원본 `data/staging/yongsan_burger_stores_staging.csv`의 24곳은 계속 미분류 상태이며 수정하지 않는다. 스타일 검수표에서 사용자가 승인한 20곳만 선택적으로 결합해 Git 제외 development asset을 다시 생성했다. 미승인 4곳은 asset에서도 `unclassified`다.

파생 asset의 스타일 분포는 `classic 14`, `smash 1`, `chicken 2`, `other 3`, `unclassified 4`다. 모든 행의 `verificationStatus=pending`은 유지되며 스타일 승인이 매장 게시 승인으로 사용되지 않는다. 게시돼 있던 노머시버거 1곳에는 사용자가 별도 UPDATE SQL을 한 번 적용했으며 다른 매장의 게시 상태나 스타일은 변경하지 않았다.

## 자동 테스트 범위

- 내부 코드와 한국어 값 파싱
- 공백·대소문자 정규화
- 빈 값·알 수 없는 값의 미분류 처리
- 사용자 표시 문구와 상세 미분류 문구
- 동적 스타일 목록의 순서와 중복 제거
- 검색과 필터 AND 결합
- 마커·결과 목록·결과 없음·선택 카드 동기화
- 검색어 지우기와 전체 선택 시 다른 조건 유지
- 상세 화면 왕복 후 검색어·필터·선택 카드 유지
- 로더 호출 1회 유지와 카메라 비이동
- 분류된 합성 staging fixture의 14/1/2/3/4 스타일 분포
- `전체`, `클래식`, `스매시`, `치킨`, `기타`, `미분류` 순서와 비건 필터 미표시
- 작은 화면, 빈 상태, 오류, 재시도와 기존 기능 회귀

2026-08-20 자동 검증 결과는 다음과 같다.

- `dart format .`: 변경 없음
- `flutter analyze`: 이슈 0건
- Flutter 테스트: 75개 통과
- Python 데이터 파이프라인 테스트: 95개 통과(Phase 4C-B 워크플로 포함)
- Android debug APK 빌드 성공

## Android 수동 검증

2026-08-20 Android 에뮬레이터의 development + staging 모드에서 다음을 사용자가 직접 확인했다.

- staging 매장 24개 정상 로딩
- `전체`, `미분류` 필터 표시 및 `미분류` 선택
- `PPS` 검색과 `미분류` 필터의 AND 결합
- PPS 검색 결과와 해당 마커 표시
- PPS 선택 후 상세 화면 진입
- 상세 화면에서 돌아온 뒤 검색어, 필터와 선택 카드 유지
- `전체` 선택 후 `PPS` 검색어 유지
- 검색어 삭제 후 24개 매장 복원
- `zzzz` 검색 시 `검색 결과가 없습니다.` 표시
- 필터 변경 시 불필요한 카메라 이동 없음
- 작은 화면에서 필터 영역 overflow 없음

위 수동 검증은 B2 승인 전의 Phase 4C-A 기록이다. B2에서 파생 asset이 여러 스타일로 변경됐으므로 다음 항목은 갱신된 합성 fixture와 자동 테스트로 다시 검증한다.

- 여러 버거 스타일 필터의 표시와 분류표 순서 정렬
- 다른 스타일 선택 시 마커 필터링
- 필터에서 제외된 선택 매장 카드 닫기
- 여러 필터의 가로 스크롤
- 데이터 재로딩 후 존재하지 않게 된 필터의 `전체` 복귀

따라서 Phase 4C-A는 필터 구조 검증까지 완료한 단계이며, 실제 매장 24곳의 스타일 분류를 완료한 단계가 아니다.

## Phase 4C-B2 수동 검증

2026-08-20 Android 에뮬레이터의 development + staging 모드에서 사용자가 다음을 직접 확인했다.

- 마커 24개 로딩
- 필터 순서 `전체`, `클래식`, `스매시`, `치킨`, `기타`, `미분류`
- `비건·식물성` 필터 미표시
- 스타일별 필터링
- `PPS` 검색과 `스매시` 필터의 AND 결합
- 승인 매장의 상세 스타일 표시
- 미승인 4곳의 `아직 분류되지 않았습니다.` 표시
- 검색·필터·상세 화면 왕복 상태 유지

development + supabase 모드에서는 노머시버거 마커, `전체·클래식` 필터, 상세 화면의 `클래식·검수 완료`, 검색과 뒤로가기 동작을 확인했다. 필터 사용으로 추가 Supabase SELECT가 발생하지 않는 기존 로컬 필터 구조는 유지된다.
