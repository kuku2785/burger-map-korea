# Phase 6A-1 공개 매장 확대 근거 조사

## 목표와 범위

현재 공개된 `verified + active` 매장 1곳에 더해 용산구 공개 매장을 최대 10곳으로 확대하기 위한 사전 조사 단계다. 게시 검수표의 pending 23곳을 모두 조사했으며, hold report의 4곳과 이미 공개된 노머시버거는 조사·추천 대상에서 제외했다.

이번 단계는 근거 조사와 사용자 승인 후보 선정까지만 수행한다. `publishDecision`, `isActive`, `verifiedAt`, 원본 매장 데이터, Flutter asset, 게시 SQL 및 Supabase는 변경하지 않았다. 추천은 승인이나 게시를 의미하지 않는다.

## 조사 기준

최근 180일 이내 공식 공지·게시물, 현재 날짜의 영업·예약·주문 상태를 제공하는 공개 페이지, 또는 서로 독립적인 최근 자료를 우선한다. 단순 검색 결과, 게시일 없는 오래된 목록, 주소만 있는 사업자 자료는 단독으로 현재 영업을 확정하는 근거로 사용하지 않는다.

매장명·지점명, 도로명주소, 기존 좌표와 주소의 명백한 충돌 여부를 각각 판정한다. 외부 공개 페이지에서 좌표를 확실히 확인할 수 없으면 기존 좌표를 유지하고 `limited_evidence`로 기록한다. 공개 근거에서 새 좌표를 만들거나 추측하지 않는다.

버거가 대표 메뉴군이거나 매장이 버거 전문점으로 소개되는지를 확인한다. 이전 스타일 승인은 게시 승인과 별개이며, 스타일 승인만으로 현재 운영 매장이라고 판단하지 않는다.

## 출처 등급

- `official`: 운영사·브랜드 공식 홈페이지, 공식 채널, 공식 주문·예약 페이지
- `public_platform`: 로그인 없이 확인 가능한 장소·예약·주문 플랫폼
- `news`: 언론 기사
- `government`: 공개 사업자·공공자료
- `independent`: 최근 방문 기록 등 독립 자료
- `other`: 위 범주에 속하지 않는 보조 자료

게시일을 확인할 수 없으면 `unknown`으로 기록한다. 다만 현재 날짜의 영업·예약 상태를 직접 제공하는 공식·공개 플랫폼 페이지는 확인일 기준 현재 상태 근거로 구분한다. 페이지가 바뀔 수 있으므로 실제 게시 직전에 다시 확인해야 한다.

## 한계와 다음 단계

공식 출처가 없는 소규모 매장은 공개 플랫폼 정보에 의존했다. 공개 플랫폼은 운영 주체가 아니며 영업시간·주소·메뉴가 늦게 갱신될 수 있다. 게시 직전 이름, 주소, 현재 영업, 버거 전문성과 좌표 충돌을 다시 확인해야 한다.

다음 단계는 사용자 승인 번호를 받은 뒤에만 진행한다. 승인된 행만 게시 검수표에서 verified + active로 변경하고, 검수 시각과 근거 메모를 기록한 다음 기존 안전 SQL 생성기를 사용한다. 이번 단계에서는 SQL, Supabase, Flutter 데이터, 원격 서비스, Git commit 및 push를 변경하지 않았다.

## 자동 검증

생성기 targeted 테스트는 합성 매장만 사용해 다음을 검증한다.

- pending만 출력하고 기존 공개 매장·hold 매장 제외
- 행 순서, storeId, candidateId, 이름, 주소, 좌표 보존
- UUID·candidateId 중복 및 좌표 오류 차단
- 근거 누락·중복·미확인 URL·미래 날짜·비밀값 패턴 차단
- 공식 근거 또는 최근 근거 2개가 없는 승인 추천 차단
- likely-closed 제안도 pending + inactive 유지
- 재실행 결정성과 `reviewerNote` 보존
- 입력 CSV SHA-256 불변

Flutter 코드와 asset은 변경하지 않았으며 기존 Flutter 회귀 테스트만 실행한다. APK/AAB는 Flutter 산출물에 영향을 주는 변경이 없어 이 단계의 필수 빌드에서 제외한다.

### 로컬 게시 검수표 결과

승인 적용기는 9곳의 `publishDecision=verified`, `isActive=true`, 승인 스타일,
실제 근거 기반 `sourceAsOf`, KST 시간대가 포함된 `verifiedAt`, 매장별 검수
근거를 원자적으로 기록했다. 기존 노머시버거 행과 미승인 14행은 모든 기존
값을 유지했다.

- 전체 24행
- 기존 verified + active 1곳
- 신규 verified + active 9곳
- 최종 verified 10곳, pending 14곳
- 최종 active 10곳, inactive 14곳
- storeId 및 candidateId 중복 0건
- 동일 입력 재실행 시 최초 `verifiedAt`과 파일 SHA-256 보존

승인 명세와 게시 검수표는 로컬 검수 데이터이므로 Git에서 제외한다.

### 신규 9행 게시 SQL

`data/staging/yongsan_burger_store_publish_expansion.sql`에는 신규 승인 9곳만
포함한다. 기존 노머시버거, #21, pending 14곳과 hold 4곳은 포함하지 않는다.
명시적 stores 컬럼 목록과 transaction을 사용하며 다음 조건을 SQL 내부에서
검증한다.

1. INSERT 전 신규 UUID 9개가 `public.stores`에 0개인지 확인한다.
2. 하나라도 존재하면 예외를 발생시켜 transaction을 중단한다.
3. INSERT 영향 행 수가 정확히 9인지 확인한다.
4. 9개 UUID가 모두 `verified + active`이고 승인된 `burger_style`인지 확인한다.
5. 조건이 하나라도 다르면 transaction을 중단한다.

같은 SQL을 두 번 실행하면 두 번째 실행은 사전 조건에서 실패하도록 설계했다.
UPDATE, DELETE, UPSERT, RPC와 `ON CONFLICT`는 없고 candidateId, 외부 Place ID,
근거 URL, 검수 메모 및 비밀값도 포함하지 않는다.

SQL 생성 시점에는 Supabase 접속과 실행, Flutter 데이터·asset 변경 및 원격
확인을 수행하지 않았다. 이후 사용자가 아래 원격 적용과 앱 검증을 직접
완료했다.

## Phase 6A 원격 적용 및 수동 검증

### SQL 무결성과 원격 적용

사용자는 실행 전에 개발용 Supabase의 `public.stores` 전체와
`verified + active`가 모두 1행이며 기존 공개 매장은 노머시버거뿐임을
확인했다. 로컬에서 계산한 신규 9행 SQL의 SHA-256
`FDD7A9BB61325AC4ED493F8BF6D7DBAE9633780565A9298C7B4B3BAE435FD5F3`가
이 문서화 전 보고값과 일치하는 것도 확인했다. SQL 파일 자체는 계속 Git에서
제외한다.

사용자가 개발용 Supabase SQL Editor에서 이 SQL을 정확히 한 번 실행했으며,
재실행하지 않았다. 실행은 성공했고 SQL 내부의 신규 UUID 0건 사전 조건,
INSERT 9행 및 verified·active·스타일 사후 조건을 모두 통과했다. 기존
노머시버거는 INSERT 대상이 아니었다.

적용 후 사용자가 확인한 원격 결과는 다음과 같다.

- `public.stores`: 10행
- `verified + active`: 10행
- `classic`: 7행
- `other`: 2행
- `chicken`: 1행
- 모든 행 `verified + active`
- 노스트레스버거 한남점 미포함 및 `needs_manual_check` 유지

신규 게시 매장은 바스버거 후암점, 브루클린더버거조인트 동부이촌점, N버거,
더백푸드트럭 해방촌점, 버거인, 한강버거, 롸카두들 이태원점, 자코비버거
이태원점, 바스버거 신용산점 9곳이다. 기존 노머시버거를 합쳐 공개 매장은
10곳이다.

### development + Supabase 앱 검증

사용자가 실제 비밀값은 로컬 실행 인수로만 전달하고 다음을 수동 확인했다.

- 지도 마커 10개 표시
- 필터 순서 `전체 → 클래식 → 치킨 → 기타`
- 자코비버거 검색, 상세 화면 및 외부 길찾기 정상
- 롸카두들 이태원점의 `치킨` 스타일 표시
- N버거 또는 버거인의 `기타` 스타일 표시
- 노스트레스버거 한남점 미표시
- 검색 초기화 후 마커 10개 복원

실제 API key, Supabase URL, Publishable key와 프로젝트 식별자는 저장소와
문서에 기록하지 않았다. 이번 완료는 용산구 공개 검수 매장 10곳 확보와 해당
앱 사용자 여정 검증에 한정된다. 전체 출시 준비, 25곳·100곳 확대, 전국 확대를
의미하지 않는다.
